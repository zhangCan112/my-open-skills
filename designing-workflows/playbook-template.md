# Playbook 模板（按需加载）

装配阶段（Phase 4）才读本文件。下面是带注释的完整模板，直接套用。

## flow.md（接口层，永远先读）

```markdown
---
name: <workflow-name>
goal: <一句话目标>
trigger: <什么时候跑这个 workflow>
status: draft
---

# Workflow: <name>

## Meta
- **成功标准:** <可观测的结果，来自 Phase 0>
- **硬约束:** <时间/成本/工具/合规，来自 Phase 0>
- **消费模式:** agent 跑（默认）/ 人跑 / 混合
- **必需输入:** [ ] <输入1>  [ ] <输入2>   ← 缺口填平后这里全勾上
- **复用能力:** skill:<X> · tool:<Y> · ...
- **已填缺口留痕:** <Phase 1 暴露、Phase 5 填平的，记一句"原本不知道 X，已确认 Y">

## L0 — 结果
<一句话：成功长什么样>

## L1 — 阶段流程
[phase1] -> [gate:?] -> [phase2] -> [gate:?] -> [phase3]

| Phase | 作用 | 用什么能力 | Gate |
|-------|------|-----------|------|
| <p1>  | ...  | tool:X / skill:Y / inline | <机检 or 人检> |

执行契约：先读本文件；执行到某 phase 才读 steps/NN-<phase>.md；上一 gate 通过才加载下一步。
```

## steps/NN-\<phase\>.md（执行到才加载）

```markdown
# Phase <N>: <phase 名>

## L2 — 步骤
1. <动作> — [tool:X | skill:Y | inline] — in: <> -> out: <>
2. <动作> — [skill:Y] — in: <> -> out: <>
   ...

## L3 — 可执行 prompt（agent 模式必填）
<这一步具体怎么做的可执行指令 / 判定标准。给 agent 看的，要精确到能直接跑。>

## Gate（机检）
- 通过条件: <可机器判定的客观标准，如"测试全绿"、"文件存在"、"返回 200">
- 失败动作: <不通过时怎么办：重试 / 退回上一步 / 停下问人>
```

## gaps.md（可选，缺口留痕）

```markdown
# 缺口分析

## Phase 1 暴露的缺口
| 缺口 | 状态 | 答案（Phase 5 填） |
|------|------|------------------|
| <不知道的东西> | 已填平/待问 | <确认后的内容> |
```

## 单文件退化模板（低于阈值时用）

把上面三块合并进**一个**文件，按顺序：Meta → L0 → L1 阶段表 → 每个 phase 的 L2/L3/gate（直接内联，不另开 steps/）。**只有规模 ≤ 阈值才允许这样**，否则违反封装原则。

## 装配检查（写完立刻自检）

- [ ] `flow.md` 自足：读完它就懂全貌 + 知道所有必需输入
- [ ] 每个 step 文件自足：执行那步不缺任何东西
- [ ] 能力引用都在 Phase 2 能力池内
- [ ] gate 都有机检条件（agent 模式）
- [ ] 规模超阈值 → 已拆目录；没超 → 单文件
