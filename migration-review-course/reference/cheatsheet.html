迁移 Review 一页速查

打印贴墙。审一次迁移，走一遍这条流水线

五步流水线

  1. 定范围 —— 一个模块/工作包，新旧两套代码路径对齐。
  2. 建清单（Business Rules Inventory） —— 逐条列业务规则：ID / 描述 / 旧位置 / 等级。分枝、守卫、switch case、side effect 全部收录。
  3. 对新代码逐条映射 —— 每条规则在新代码找实现，找不到就是差异。
  4. 分类 + 验证 —— 标（第 3 课）、边界与不变量（第 4 课）、按风险决定上升几级验证梯队（第 5 课）。
  5. 出报告 + 等签发 —— 逐规则表 + 差异表 + 结论（放行/补救/待专家）。领域专家签字后才算完。

差异分类速记

分类怎么认
MISSING整个行为没了
PARTIAL还差分支/case
DIFFERS都在但是行为变了

每差必填：类别 + 严重度 + file:line（新旧各一个）+ 是否"故意不同"。

隐形行为四查（第 4 课）

默认值 / fallback · 排序保证 · 时序（超时/重试/限速）· 日志/审计 · 错误格式与错误码。每个模块过一遍这五样。

验证梯队怎么选（第 5 课）

风险最低层级
低（读多写少，纯计算）Tier 1 静态比对
中（有相对路径/兼容要求）Tier 2 表征测试（golden master）
高（金融/状态机/对外契约）Tier 3 影子流量 + 数据对账（Tier 4）

报告骨架（第 6 课）

1. 汇总（数量 + 结论）
2. 逐规则表
3. 行为差异（故意改进？可接受偏差？回归？）
4. 缺失规则（为何缺、风险、动作）
5. 边界与不变量
6. 集成点（API/数据格式/下游）
7. 推荐 + 签字
