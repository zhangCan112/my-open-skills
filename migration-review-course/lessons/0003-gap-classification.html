Lesson 03 · Gap Classification

差异三分类：MISSING / PARTIAL / DIFFERS

把笼统的"感觉不对"变成可执行、可复核的分类体系

为什么需要分类

评审时随口说"这里不太对"毫无价值——它不可复核、不可计数、不可转成 bug list。parity-check agent 的做法是：把源端每个行为完整描一遍，然后给每个差异贴一个类别。分类让审查结果可以被核验、被排序、被驱动为修复动作。

三分类定义

分类含义例子严重度
MISSING 源端有、目标端完全没有 旧代码有降重逻辑，新代码完全没写 高——功能丢了
PARTIAL 有，但不完整（少了分支、case、边界） 旧代码两种会员折扣，新代码只实现了白金卡 中，易被漏检
DIFFERS 都在，但行为逻辑发生变化 旧代码 5 日生效，新代码改成 7 日 高——业务被改写

检查清单的时机：何时收手

  • 目标端仅当存在明显注释说明"有意省略"时，才不标 MISSING——否则一律按缺漏处理。
  • 每条差异既标记分类，也标记严重度（高/中/低）和一个《对应文件:行号》，方便回溯。
  • differs 要写“差异点”，不能只写“行为不同”——具体到哪个字段、哪个分支。
一个朴素但够用的提醒：分类不解决"要不要修"的价值判断——那部分用"意图推断"（intent inference）去问领域专家，而不是自己拍板。分类负责"记差异账"，意图判断（将在后面的课程展开）负责"区分故意改进 / 可接受偏差 / 回归"。

Quiz

旧代码每个输入都做：null 检查 → 转换 → 持久化。新代码只做了转换与持久化，没有任何 null 处理。这属于？

旧代码有 null-guard，新代码完全没有这个行为，是"整个行为丢失"，属于 MISSING。PARTIAL 是行为还在但缺了一些分支。

旧代码用"字符串戳 13 位时间戳"，新代码改用"秒级时间戳"。两个都在、都正常工作，但精度不同。这属于？

行为都在，但发生了变化（格式/精度），属于 DIFFERS。这种最容易混过 human review，务必列进差异报告。

主阅读源
