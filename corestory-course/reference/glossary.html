术语表 / Glossary

贯穿全部 18 课的核心术语，本课程约定始终沿用这些定义。每次学习新课时先回顾本节。

平台与角色

CoreStory
代码智能平台：用 AI 从源码反向工程出规范（PRD、TechSpec、用户故事等），形成"持久化智能层"。来源：官方 What is CoreStory
Ingestion（摄取）
把仓库吸收为可查询的代码智能模型的过程。分析结果反映的是摄取时刻的代码快照——关键发现需对照当前源码复核。
Code Intelligence（代码智能）
从源码、PRD、技术规格、代码历史、架构分析中综合出的系统如何工作的知识，可被 Agent 查询。
MCP（Model Context Protocol）
Agent 与 CoreStory / Jira 等服务器通信的标准协议。CoreStory MCP 端点：https://c2s.corestory.ai/mcp，用 Authorization: Bearer mcp_...。
Expert（专家角色）
CoreStory 角色之一：解释系统"应该怎么工作"——架构、设计意图、不变量、业务规则、历史背景。
Navigator（导航角色）
CoreStory 角色之一：指出具体文件、方法、扩展点、代码路径——"代码在哪、改哪里"。
Verifier（验证角色）
现代化阶段的角色：对照旧系统与新实现，证明行为等价。
Gap Analyzer（差距分析角色）
Feature Gap Analysis 中的独特角色：把功能规范与现有系统逐项比对，标出"已有/缺失/需改动"。
Conversation（对话线程）
CoreStory 中的持久化会话。每个任务开一个，命名清晰，完成后加 RESOLVED 前缀——形成可检索的"机构知识"。

核心交互范式（所有 playbook 共用）

Expert before Navigator（先专家后导航）
先问"系统设计上该如何工作"，再去找具体问题/代码路径。先理解意图，偏差才容易现形。
Specification before Code（先规格后代码）
测试/实现前先提取"应当的行为规格"，而不是先读实现代码照着写测试。
Conversation lifecycle（对话生命周期）
选项目（list_projects）→ 建对话（create_conversation）→ 查询（send_message）→ 完结改名（rename_conversation 加 RESOLVED）。

现代化（六阶段框架）

7 Rs 现代化策略
Retire（退役）/ Retain（保留）/ Rehost（升降级搬迁）/ Relocate（虚拟机搬迁）/ Replatform（平台化）/ Refactor / Re-architect（重构再架构）/ Repurchase（采购 SaaS）。本 playbook 以 Refactor / Re-architect 价值最高。
Strangler Fig（绞杀藤模式）
Martin Fowler 提出的增量现代化模式：Transform（建新版）→ Coexist（共存、用 facade 路由流量）→ Eliminate（验证后退役旧版）。默认执行模式。
TCE 循环
Transform → Coexist → Eliminate 的缩写，每个工作包的执行结构。
Branch by Abstraction（抽象分支）
对无法在外部拦截的内部组件（共享库、数据访问层），在代码库内引入抽象层、新旧实现并存、逐个切换调用方。
Parallel Run / Shadow Traffic（影子流量）
把生产请求副本同时打到新旧系统，对比响应。临界值：关键服务差率 <0.01%，一般服务 <0.1%。来源：Microsoft Engineering Playbook。
Confidence Protocol（置信度协议）
对 AI 派生发现分级：Verified（已验证）/ High-confidence（高置信）/ Hypothesized（猜测）/ Contradicted（矛盾）。决定需要多少人工复核。
Behavior tags（行为标签）
每个行为标迁移意图：PRESERVE（原样保留）/ MODERNIZE（现代化实现）/ CHANGE（有意变更）/ NEW（新增）/ RETIRE（移除）。若 CHANGE+NEW 超过 20% 提示从现代化滑向重写。
Work Package（工作包）
最小可独立部署的迁移单元，含 Transform/Coexist/Eliminate 三阶段、验收标准、依赖、工作量估计。
ADR（Architectural Decision Record，架构决策记录）
阶段三产物：记录当前状态、选定策略、目标架构、迁移范围、约束、风险、备选方案、审批。
Behavioral Equivalence（行为等价）
新旧实现"输入条件、逻辑、副作用、错误处理、输出"语义一致。
Characterization / Golden Master Testing（刻画测试 / 金标测试）
Michael Feathers 提出：用大量输入抓取旧系统输出作为"金标"，新实现必须匹配。旧系统行为即规范。

业务规则提取

BR-XXX 编号
业务规则清单的每条规则编号（如 BR-007），跨阶段引用（阶段二产出、阶段六验证）。
Claim Type（声明类型）
规则声称类型：Workflow / Constraint / Validation / Default / Calculation / Authorization。决定验证优先级。
Enforcement Point（强制执行点）
真正拒绝非法输入的那一行代码，而非字段声明处。找不到就降级为"Declared but not enforced"。
Invariants（不变量）
无论输入如何必须始终成立的性质，如 coord_names ⊆ variables.keys()。分类：数据完整性 / 状态机 / 引用 / 安全 / 时序。

Spec-Driven Development & 测试

Delta Spec（增量规格）
只描述"变化的部分"：不变量、要复用的现有组件、新增/修改组件、验收标准。避免绿地式重复规范。
Six-Phase SDD
Ground（地面/基于架构了解）→ Specify（写增量规格）→ Validate（架构 pre-mortem 验证）→ Plan（文件/依赖顺序）→ Implement（TDD）→ Verify & Capture（逐条核验 + 记录）。
Reuse-first / Invariants-first
规格先写"绝不能破坏的不变量"，再写可复用组件；复用查询常能砍掉 30–50% 的规格工作。
Pre-mortem（事前剖析）
实现前让 CoreStory 审查规格：模式冲突、缺失依赖、失败模式。单机 SDD 工具做不到。
Code-mirroring tests（代码镜像测试）
断言"如何实现"（mock 调用、签名）。重命名就坏、重构就碎——"循环断言的伪覆盖"。
Specification-driven tests（规格驱动测试）
断言"应当的结果"（输出、状态变化）。任何保留业务规则的重构都能存活。例：test_order_rejected_when_below_minimum_amount。
Behavioral inventory（行为清单）
测试生成前的规格提取：验收标准、验证规则、状态迁移、授权矩阵、不变量、隐式行为、计算。
Flakiness management（测试不稳定管理）
E2E 用条件等待而非固定延时、隔离测试数据、稳定环境；新套件至少连跑 3 次确认稳定性。

集成与技能

Rovo MCP Server
Atlassian 官方 MCP 服务器（云托管，支持 Jira/Confluence/Compass，OAuth 2.1）。端点 https://mcp.atlassian.com/v1/mcp。
SKILL.md
Agent 技能文件（Claude Code 装在 .claude/skills/<name>/SKILL.md）。本课程 0018 课教你如何写它。
AGENTS.md
跨 harness 的技能分发单文件规范，被 Codex、Aider、Cursor、Gemini CLI、Windsurf 等读取。
Spec Kit
GitHub 的 SDD 框架，提供 /speckit.constitution、/speckit.specify 等命令生成结构化规格产物，存于 .specify/memory/。
