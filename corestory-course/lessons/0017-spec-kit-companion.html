Lesson 17 · 高级主题

Spec Kit Companion（与 GitHub Spec Kit 集成）

CoreStory 给架构地基，Spec Kit 给结构化书写。两个工具互补：一个管"写什么"，一个管"确认是现实"。

分工的本质

CoreStory 告诉你架构实际上是什么；Spec Kit 给你一套把它写下来的统一格式（机器可读、可版本控制、可 PR 审查）。谁也不替代谁：CoreStory 给出 grounding，Spec Kit 给出 artifact 结构。来源

相位 ↔ 命令映射表（记忆核心）

SDD 相位Spec Kit 命令整合模式
1 · Ground/speckit.constitutionCoreStory 发现（架构/约定/不变量/技术决策/测试）喂入 constitution
2 · Specify/speckit.specifydelta spec（不变量 + 复用 + 增量）约束 spec
3 · Validate（无对应）仅 CoreStory——对 .specify 产物做架构 pre-mortem
4 · Plan/speckit.plan + /speckit.tasks已验 spec 喂计划与任务拆分
5 · Implement/speckit.implement标准 TDD 实现
6 · Verify & Capture（无对应）仅 CoreStory——验证不变量并捕获知识
核心洞察 相位 3（Validate）与相位 6（Verify & Capture）没有 Spec Kit 等价物——这是 CoreStory 填的坑。Spec Kit 结构化产物，CoreStory 验证它是否符合现实。

安装与初始化

uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
specify --version
specify init my-project --ai claude    # 或 copilot / cursor-agent / gemini / opencode 等

关键理念：CoreStory before Spec Kit（每相位都先 CoreStory）

  • Constitution 是最有杠杆的产物——把最多的查询时间投给它。没有 CoreStory 它会写出一份"干净代码"式通用宪法；有 CoreStory 它就具体到 UserService、指明异步都用 TaskQueue、记下审计敏感模型强制软删除。它是活文档，特性上线后要更新。
  • 阶段一 Ground 后把架构发现粘进 /speckit.constitution 提示（示例段），阶段三把 spec.md 黏进 CoreStory 做 pre-mortem。
  • 两个"只有 CoreStory"的相位别跳过——跳过 Phase 3 会得到"重复建已有服务"的愚蠢建议。

规格产物存放（可 PR 审查、可版本化）

产物位置由谁创建
Constitution.specify/memory/constitution.md/speckit.constitution
Feature spec.specify/memory/features/{name}/spec.md/speckit.specify
Technical plan.specify/memory/features/{name}/plan.md/speckit.plan
Task breakdown.specify/memory/features/{name}/tasks.md/speckit.tasks

陷阱排查

  • 命令不可用 → 检查 .specify/ 存在，或 specify init --here --ai <agent>。
  • 分成太通用 → 先查 CoreStory 再把具体信息贴进提示（通用输入出通用产物）。
  • Spec Kit 建议新建已存在的服务 → 相位 3 没做或没做充分；问 CoreStory "应该复用哪个已有服务"。
  • 产物与对话分叉 → CoreStory 对话是事实源，用刷新后的产物内容重跑验证。
