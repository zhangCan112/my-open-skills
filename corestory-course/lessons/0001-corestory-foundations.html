Lesson 01 · 平台基础

CoreStory 平台与核心交互范式

先建立"你能问出什么问题、机器如何回答"的心智模型——这是后续所有 playbook 的地基。

CoreStory 是什么？

CoreStory 是一个代码智能平台：用 AI 从源码反向工程出规范。你接入仓库后，它摄取（ingest）整个代码库，产出一个持久化智能层——一个"可动态查询的代码库模型"，并持续跟随源码更新。

它解决的根本问题：文档陈旧、部落知识存在人脑里、AI 编码工具因缺少场景而幻觉。CoreStory 让人类和 AI 共享同一份准确的系统行为理解。来源

摄取（Ingestion）工作原理

输入：公开仓库、私有仓库、直接文件上传。输出：聊天界面 + 一组标准规范输出（executive summary、user personas、user stories、data models、API specifications、integration points）。接入方式：MCP server 与 REST API。来源

关键心智：快照 分析反映的是"摄取时刻"的代码快照。如果源码之后变了，关键发现要与当前源码复核——这是 M&A 尽调里的强制步骤。

给 Agent 的两个角色：Expert 与 Navigator

角色回答的问题示例
Expert（专家）系统应当如何工作、设计意图、不变量、业务规则、架构模式、设计历史。"resetting a Dataset 时 _coord_names 应如何更新？"
Navigator（导航）具体文件、方法、扩展点、代码路径在哪。"dataset.py 中 4180 行附近是哪块逻辑？"

现代化阶段还有第三个角色 Verifier（验证）——对比旧版与新实现，证明行为等价。来源

MCP 与 8 个工具

Agent 通过 MCP（Model Context Protocol） 访问 CoreStory。MCP 端点：https://c2s.corestory.ai/mcp，认证 Authorization: Bearer mcp_YOUR_TOKEN。8 个工具在所有 harness（Claude Code、Cursor、Copilot、Windsurf、Devin、Factory）下一致：

工具作用
list_projects列出你的项目（确认摄入完成）
get_project_prd取合成 PRD（业务需求上下文）
get_project_techspec取合成 TechSpec（架构/数据模型）
create_conversation为任务建持久化对话线程
send_message查询代码智能（最常用）
list_conversations回顾已有对话
get_conversation取某个对话历史
rename_conversation完成后加 "RESOLVED" 前缀
重要陷阱 PRD / TechSpec 往往巨大到塞不进上下文窗口。不要整篇读——用 send_message 去问它内容。CoreStory 已摄取这些文档，能针对性回答问题。

核心交互范式（6 步）

  1. 选择项目：list_projects 确认目标，检查摄取完成。
  2. 创建对话：create_conversation，用描述性标题（如 "Ticket Implementation: #6992 - CSV export"）。
  3. 问 Expert：系统行为、不变量、架构。
  4. 问 Navigator：文件/方法/扩展点。
  5. 行动：实现/测试/文档。
  6. 闭环：rename_conversation 加 "RESOLVED/COMPLETED" 前缀——对话成为"机构知识"。

提问的小撇步（官方 Best Practices）

  • 越具体越好：不要说 "Tell me about the order system"，要说 "What is the validation logic? What fields are required, minimum amounts, stock checks?"
  • Expert before Navigator：先理解"应当如何"，再找"改哪里"。这让你更容易看见偏差与捷径。
  • 一次任务一个对话；善用命名；复用旧对话。
