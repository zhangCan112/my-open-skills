Lesson 14 · 测试与验证

Behavioral 覆盖 + E2E 测试生成

Spec-Driven Test Generation 的两个执行子流程：单模块行为测试（10–30 用例）与关键用户旅程 E2E（5–15 场景）。

上篇：Behavioral Test Coverage（核心子流程）

痛点是"测试套件从内部腐烂"——覆盖率跟着新鲜度而不是重要性走：最新代码测得好，真正重要的老代码没人测。核心机制：Specification before Code——先向 CoreStory 提取行为规格，再生成测试。来源

六相位速览

  1. Setup & Scoping — 选项目、查旧对话（有 Business Rules 清单直接消费）、建 Test Generation - <scope>；范围：模块（10–30）/ 域（30–80+）/ 全系统（80+ 分成多会话）。首次选"有缺口 + 高业务价值"的单模块。
  2. Behavioral Inventory（Expert） — 按类提取：验收标准、验证规则、批量状态迁移（合法 + 非法）、授权规则（角色 × 操作）、不变量与边界、隐式行为（"团队 just know 但从未写下来——往往最高价值用例"）、计算/转换公式。
  3. Convention Discovery（Expert + Navigator） — 框架/目录/命名、夹具模式、断言风格、mock 工具；再读 2–3 个代表性测试确认。
  4. Coverage Gap Analysis（Navigator） — 分类 已测 / 弱（仅 happy path）/ 未测 → gap 矩阵 → 按业务重要性与破风险排序。HITL 门禁：生成测试前让人审规格与优先级（错规格 → 自信地错断言）。
  5. Generation & Validation — 逐条生成（用项目夹具、断言行为规格、docstring 挂接规则 ID 如 BR-012）；跑测试按失败类型分类（setup 失败=改测试机制；断言失败=发现：规格错或代码错，标给人审，绝不削断言去迁就现在行为）；对关键不变量做手工变异检查（临时改源码破坏规则，确认测试抓得住，恢复）。
  6. Completion & Capture — 覆盖率汇总 → 提交（模板：类型清单 + 总数 + "无回归"）→ 改名 RESOLVED - Test Generation - ...。

下篇：E2E Test Generation（旅程级）

引子：E2E 是最贵、最脆、最后真正最有用的测试。多数套件是"重大 bug 上线后某人补了一条"。CoreStory 作为 Journey Expert 从 PRD 提取用户故事/验收标准/关键路径 + 从代码库看路由/API/数据流。来源

八步走

  1. Setup — 取项目、建 E2E Test Generation - <scope>；范围：单旅程（3–8 场景）/ 旅程集群（8–15）/ 核心旅程系统级（15–30）。"10 个结构良好的旅程测试胜过 50 个浅层点击。"
  2. Journey Extraction — happy path（用户每步看到啥/输入啥/调啥 API/状态如何变化）、unhappy paths（验证失败、网络错误、部分完成状态——"用户卡住的地方最该测"）、前置条件、数据需求。
  3. Convention Discovery — E2E 框架、页面对象/选择器策略（优先 data-testid 与 roles，别用脆弱 CSS）、夹具/seed、认证方式；读 2–3 个代表文件。
  4. Journey Prioritization — 按收入影响 / 用户频率 / 失败严重性 / 复杂度。HITL 门禁：E2E 维护成本高，人先确认选旅程值得投。
  5. Generate + Stabilize — 先生成 happy path（查命名/选择器/夹具）→ 跑 & 稳定（失败分类：selector 错、超时、状态错、断言错）→ 再 unhappy path → 全量跑 至少 3 次 防 flaky。
  6. Flakiness 管理 — 条件等待而非固定延时、每测隔离数据、测试环境禁动画、重试只对瞬时基础设施问题、稳定专用环境。
  7. Completion — 汇报：Journeys inventoried: X · Happy path: Y · Unhappy path: Z · Remaining: ... → 提交（模板）→ 改名 RESOLVED - E2E Test Generation - ...。

两者如何互补（金字塔原则）

Behavioral 测试抓逻辑 bug；E2E 抓集成失败、UI 回归、跨组件断了。E2E 在最顶，别重复 behavioral 已覆盖的逻辑。命名用"旅程"而非"页面"，缺口处一目了然。
