Lesson 16 · 集成

Using CoreStory with Jira

把 Jira 当收发包层、CoreStory 当代码智能层、Agent 当协调者——四种日常工作流解放你的 sprint。

三方编排模型

构件角色
Jira MCP Server收/发：读 ticket、回评论、建 issue、转状态
CoreStory MCP Server代码智能：架构、相关文件、模式与依赖
AI Coding Agent协调者：从 Jira 拉、问 CoreStory、实现、写回 Jira

典型流程：Jira ticket → CoreStory 分析 → 实现 → 回写 Jira。注意：CoreStory 没有原生 Jira 插件，集成完全走 MCP。来源

四种工作流

Workflow 1 · 解析工单（核心）

"Fetch Jira ticket PROJ-1234 and resolve it using CoreStory for code intelligence."

拉 ticket（概要/描述/AC/优先级/标签/link）→ 建 CoreStory 对话 → 查架构 → TDD 实现 → 回写实现摘要 + 文件清单 + 测试结果 → 转状态（如 In Progress → In Review）。含可选定制：跟帖 root-cause、文件改动、测试结果，然后转 "In Review"。

Workflow 2 · 丰富 ticket（只读，练手用）

Read Jira ticket PROJ-5678 and use CoreStory to add implementation context.
I want to know: which files are involved, what patterns to follow,
and what the acceptance criteria should be.

Agent 回帖结构化分析：Affected Files / Recommended Pattern / Suggested Acceptance Criteria / Estimated Complexity。批量版：一次给 3 张 ticket 各加分析。

Workflow 3 · 起草新 ticket

Use CoreStory to analyze the authentication module in my project.
If you find any gaps in test coverage, security concerns, or tech debt
issues, create Jira tickets for each in the PROJ project.

让 Agent 查模块，把可行动项（缺测试、安全缺口、代码质量问题、文档缺口）转成结构化的新 ticket（可指定类型 / 打标签 / 分配 sprint）。

Workflow 4 · 分诊与估时（sprint 规划利器）

Read these Jira tickets and give me an implementation assessment for each:
PROJ-100, PROJ-101, PROJ-102, PROJ-103

每个 ticket：拉详情 → 查 CoreStory（文件、复杂度、依赖、测试覆盖）→ 输出评估（复杂度 S/M/L/XL、影响文件、风险、建议路径）。可汇总成表：ticket ID | 摘要 | 复杂度 | 关键风险 | 建议 sprint。

Jira MCP 配置（两选一）

  • Option A · Atlassian Rovo MCP（推荐，Jira Cloud）：云托管，OAuth 2.1，支持 Jira/Confluence/Compass。端点 https://mcp.atlassian.com/v1/mcp（本地代理用 npx mcp-remote@latest ...）。
  • Option B · 社区服务器：mcp-atlassian（Python，Cloud + Server/DC）或 @mcp-devtools/jira（Node，Jira 专注）。用 Jira API token（id.atlassian.com 生成）。
权限即边界 Agent 只能看到/修改你账号能访问的；Rovo 需组织管理员放行 AI 工具连接。转状态只在你允许的 workflow 转换范围内。商店善用——先做只读 workflow 2，建立信任再上自动解析。

最佳实践

  • 每处理一个 ticket 单独开一个实现会话；批量只用于 enrichment / triage / 起草。
  • 打统一标签（如 corestory-assisted）追踪 AI 处理的工单。
  • CoreStory 与 Jira 说法冲突时：架构以 CoreStory 为准，需求/AC 以 Jira 为准。
  • ticket 描述本身要高质量（质量进 → 质量出）。
