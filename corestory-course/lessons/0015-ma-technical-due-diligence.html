Lesson 15 · 高级主题

M&A Technical Due Diligence（并购技术尽调）

传统尽调（CTO 访谈 + 抽样）只覆盖不到 10% 的代码库——风险藏在没人读的那 90% 里。尽调的核心是把整个标的代码语义理解放大到全量。

为什么传统尽调会漏

CTO 访谈、人工抽样、文档翻看——覆盖 不到 10% 的代码库。硬编码密钥、深埋三层之下的 GPL 依赖、PII 在被遗忘的微服务里裸奔……都在那 90% 里。CoreStory 摄取并语义理解整个标的仓库，给尽调团队一个能对着全量（而非样本）回答具体风险问题的 AI 分析师——Expert（系统如何运转、数据流）与 Navigator（风险藏在哪个文件、哪行）。来源

四相位工作流

  1. Setup（Orientation）— 确认标项目、取规范概要、建命名线程（每工作流一个）：[Diligence] TargetName - Technical Risk Audit。
  2. Interrogate（风险质询） — 用 send_message 按四个风险域问具体问题：
    风险域示例查询
    技术债与过时"列出跑在 EOL/不支持版本上的所有服务/模块；给出当前版本、最新稳定版、升级路径是否有破坏性变更。"
    安全与密钥"找出所有硬编码 API key/密码/token 的代码位置，给文件路径 + 行 + 用途。"
    许可与开源风险"为所有三方依赖给出完整 BOM，标出 GPL/AGPL/SSPL 等 copyleft 库及其对收购方的义务。"
    数据与 PII"画出 PII 的收集/传输/存储流程，标出各阶段是否加密（在库在途）。"
  3. Cross-Reference（交叉验证） — 对关键发现（安全、许可、PII）回源码确认。注意 intake 快照可能过期。
  4. Synthesize（研判） — 综合成 Technical Due Diligence Report，改名 RESOLVED - [Diligence]...。对话历史即审计轨迹。
快速风险审计（给一周尽调的 PE） 核心六步 + 全量模板，将传统 2–4 周压缩到 24–48 小时。最终产出 Issue | Location(文件) | Severity | Impact 表，Top 5 deal-affecting findings 高亮。

报告结构（6 节）

Executive Summary（Top 3–5 影响 deal 风险/估值）→ Critical Risks（安全/许可/PII，各带文件证据 + 严重度）→ Technical Debt → Architecture Overview → Integration Assessment（与收购方平台合并的摩擦点）→ Recommendations（修复优先级 + 关了仓时间表）。

最佳实践

  • 每工作流独立对话（安全 vs 集成 vs 许可分开）；先从合成规范起，再下钻。
  • 每个发现都要文件路径；拒绝泛泛指令；对关键发现必须回源码交叉核。
  • 用 "Enumerate with evidence / Trace a flow / Compare to standard / Assess coverage / Find patterns / Quantify scope" 六种调查模式。

随堂测验
