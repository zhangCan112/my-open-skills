# 01 · 设计原则与骨架约束(必读)

> 本文件是整个设计的**承重墙**。开发与新手设计师在任何"实际情况比设计复杂"的时刻,先回到这里。十条不变量之下,你可以自由发挥;之上,必须停手走偏差流程。

---

## 一、十条不变量(Invariants)

### INV-1 主题令牌零硬编码
任何颜色、字体、圆角都必须来自 `tokens/design-tokens.json` 中声明的角色,最终绑定 `--vscode-*` CSS 变量或 `ThemeColor`。
- **为什么**:扩展必须自动适配用户的一切主题(含高对比度),硬编码 = 破相。
- **违反症状**:用户换 Light+ 主题后出现白底白字;高对比度下状态不可辨。
- **复杂时怎么办**:需要一种"新颜色"时,**禁止造 hex**。去 §四 的角色表找最近语义的角色;确实没有 → 在决策日志登记"申请新角色",由设计把角色加进 tokens(同时补 3 个主题值),再使用。开发不得自行加色。

### INV-2 状态三重编码
每个差异状态必须同时用 **颜色 + 图标 + 文字** 表达,三者语义一一对应(见 `assets/08-status-badges.svg`)。
- **为什么**:色盲用户、高对比度主题、截图打印场景下仅靠颜色会丢信息。
- **违反症状**:测试同学把显示器调成灰度后分不清"仅在 A"和"仅在 B"。
- **复杂时怎么办**:新增状态类型时,必须同时给出三件套并登记进 08 号图纸与 tokens;找不到合适图标 → 用文字徽标兜底,不允许只上颜色。

### INV-3 结果判定唯一来源(单一事实)
**一次比较 = 一个纯函数**:`(文件A, 文件B, 规则集) → DiffResult[]`。每个键恰好一个有效状态;侧栏树、报告表格、徽标计数、状态栏,**全部从同一份 DiffResult 派生**,任何界面不得私有重算。
- **为什么**:四处计数不一致是此类工具最快的信任崩塌方式。
- **违反症状**:树里显示 14 处、表格过滤条 15 处、状态栏 13 处。
- **复杂时怎么办**:新增展示面(如 SCM 装饰)时,只能消费 DiffResult;需要新维度(如"仅安全相关")→ 做成 DiffResult 上的**派生过滤器**,不改判定函数。

### INV-4 规则永远透明、可逆、可审计
规则对结果的影响必须:(a)在结果中可见(≈ / ⊘ 独立分区或徽标 + 命中规则名);(b)可随时开关且立即生效;(c)落到 `rules.json`,可 diff、可提交。
- **为什么**:用户最怕"工具偷偷吞差异"。
- **违反症状**:用户发现两个值明明不同却没报,且找不到原因。
- **复杂时怎么办**:任何新规则类型,必须同时回答三问:"结果里怎么显示命中?在哪一键关掉?写不写进 rules.json?"三问缺一不可。

### INV-5 侧栏导航、编辑器详情,职责不互换
侧边栏只做**浏览、选择、过滤、开关规则**;一切"看值、看内容"的详情都在编辑器区(内置 diff 或 Webview 报告)。侧栏永不展示大段值内容。
- **为什么**:符合 VS Code 用户的肌肉记忆;保证小屏侧栏也不挤。
- **违反症状**:有人想在树节点 tooltip 里塞完整 JSON。
- **复杂时怎么办**:详情需求一律进编辑器区;侧栏最多展示**单行摘要**(约定 ≤40 字符截断)。

### INV-6 树层级 = 文件自身的层级
分组顺序固定为:文件 → 状态 → 键的原始嵌套路径。不为"好看"发明额外分组(如按字母、按模块注解)。
- **为什么**:用户对照原文件找键,层级一致才能心智零翻译。
- **复杂时怎么办**:键太深(>6 层)时允许默认折叠深层,但**层级本身不许合并或改名**。

### INV-7 大结果不卡死
≥1000 条必须列表虚拟化;搜索防抖 180ms;比较可取消;全部计数 O(1) 缓存于 DiffResult。
- **为什么**:企业项目单文件数千键是常态。
- **违反症状**:打开 8000 键的报告表格直接白屏 3 秒。
- **复杂时怎么办**:加任何"全量渲染"的新视图前,先过性能预算(见 03 文档 §性能)。

### INV-8 键盘与读屏全量可达
每个鼠标动作都有键盘路径;每个状态变化有可感知的反馈(焦点/文本/通知);对比操作支持 F7 无障碍查看器(内置 diff 免费获得)。
- **复杂时怎么办**:自绘控件(如开关)必须补 role/aria/焦点环;做不到无障碍的方案直接否。

### INV-9 渐进式披露
默认路径只暴露:选项目 → 看差异 → 修。规则源码、脚本、Schema、按状态分组等进阶能力,永远"一键可达,但绝不挡路"。
- **违反症状**:首屏出现 6 个按钮问用户要配置。
- **复杂时怎么办**:新功能先问"小白第一次见到它会卡住吗?"会 → 收进进阶层。

### INV-10 入口按熟练度分层,不引导去命令面板
UI 上只引导可视入口(活动栏视图、右键、行内按钮);命令面板命令照常注册,但文案、教程、引导**永不指向它**。
- **为什么**:用户裁决(2026-10-28):命令面板对小白不友好。
- **复杂时怎么办**:写文案时出现"按 Ctrl+Shift+P…"一律删除,改为可视入口的说法。

## 二、骨架布局(哪些固定、哪些可变)

图:`assets/01-overview-layout.svg`

| 区域 | 尺寸 | 可变性 | 约束 |
| --- | --- | --- | --- |
| 活动栏图标 | 24×24 图标,48px 条(VS Code 托管) | 不可改 | 顺序排在资源管理器之后;badge 显示活跃比较的差异总数 |
| 侧栏宽度 | 默认 300px,随用户拖拽(260–500) | 用户控制 | 内容须在 260px 下不破版(设计以 300 出图) |
| 侧栏-差异视图 | 树,行高 22px(VS Code 默认,勿改) | 高度随折叠 | 永远是容器内第一个视图 |
| 侧栏-规则视图 | 同上 | 可折叠 | 默认折叠到 40% 高度以下;差异视图存在时自动给差异让位 |
| 编辑器-报告标签 | Webview,单例(重复触发 reveal) | 自适应 | 文件对切换用页内芯片,不开新标签 |
| 编辑器-键级 Diff | `vscode.diff` 只读虚拟文档 | 自适应 | 每键一个虚拟文档对;语言 id 跟随源文件 |
| 状态栏项 | 左区,短文本 `$(diff) N 处差异` | 不可移到右侧 | 仅存在活跃比较;点击 reveal 差异视图 |

**弹性规则**:除上表"不可改"项,其余间距、列宽、面板高度可按实现微调 ±20%;但**信息层级顺序**(谁在上、谁先被看到)不允许调换。

## 四、状态判定模型(核心中的核心)

一次比较产出一个不可变的 `DiffResult`:

```
输入:sideA: ParsedFile[], sideB: ParsedFile[], rules: RulesConfig
输出:DiffResult {
  items: KeyDiff[]        // 每个"键对"恰好一条,含 status
  files: FilePairResult[] // 文件级:配对关系、解析错误
  stats: {total, byStatus} // 所有计数唯一来源
  generatedAt: timestamp
}
KeyDiff.status 判定优先级(从上到下,命中即停):
1. err    任一侧解析失败(挂文件级,键不参与)
2. ign    命中忽略 glob / 脚本返回 "ignore"
3. equ    命中值等价 / 类型宽化 / 脚本返回 "equal"
4. type   同键,值类型不同(且未被 3 覆盖)
5. mod    同键,值不相等
6. onlya  仅 A 有(B 缺失)
7. onlyb  仅 B 有(A 缺失)
8. same   同键同值同类型(默认隐藏,统计保留)
```

- **规则匹配顺序** = rules.json 中的书写顺序,首个命中生效(`ignore` 优先于 `equivalence` 检查)。
- **所有 UI 计数** = 对 `stats.byStatus` 的查询,禁止二次统计(INV-3)。
- **规则开关** = 重新调用判定函数(纯函数,瞬时),而非在 UI 层打补丁。

## 六、偏差处理流程(现实比设计复杂时)

```
遇到设计未覆盖的情况
 ├─ Q1 是否违反十条不变量?
 │   ├─ 否 → 自行设计,在 README 决策日志登记:情况/决定/理由。继续。
 │   └─ 是 → Q2 是否存在"不变量的最小让步版"?
 │        ├─ 是(如:为了性能给树加虚拟化,不改变层级)→ 采用,登记,标注"让步于 INV-7"。
 │        └─ 否 → 停止。整理:场景截图 + 目标 + 与哪条冲突 + 两个备选,找资深设计仲裁。
 └─ 通用守则:先补决策日志,再写代码;图纸与实现不一致时,以「不变量 > 图纸 > 原型细节」为序。
```

**新手最常见的三类跑偏与自我检查**:
1. 想加颜色 → 查 INV-1 角色表,别造色。
2. 想在树里塞更多信息 → 查 INV-5,摘要 ≤40 字符,详情进编辑器。
3. 想自己数个数 → 查 INV-3,只读 stats。
