Config Diff — VS Code 扩展 UI/UX 设计原型

比较两个项目的配置文件:键缺失 / 键多余 / 值不同 / 类型不同;支持规则配置(文件配对 · 值等价 · 忽略 · JS 脚本)—— 交互式高保真原型

设计依据:官方 UX Guidelines 一手调研 树视图(导航)+ Webview(报告)+ 内置 Diff(详情) 主题变量驱动 · 无障碍三重编码 规则即代码 · 简单规则表单化,复杂逻辑脚本化
🧭
复用既有心智,零学习成本

沿用 VS Code 官方「Select for Compare → Compare with Selected」两步比较模型,命令面板 / Explorer 右键 / 活动栏三入口收敛到同一流程。

🌳
四分区结果树,先看全貌

值不同 / 类型不同 / 仅在 A / 仅在 B,分区标题带计数,视图标题徽标显示总数 —— 「显示数据用 Tree View」是官方规范。

🔍
键级详情交给内置 Diff

点击任一键,用 vscode.diff 打开两侧值的并排对比,免费获得 gutter 着色、变更跳转与无障碍差异查看器。

📊
Webview 只做原生做不到的

数千键的扁平表格 + 实时计数过滤条 + 防抖搜索,遵循官方「Webview 克制使用」红线,颜色全部取自主题变量。

🧩
规则:卡片化,不读 Schema

规则底层是 JSONC + JSON Schema(可校验、可共享),界面呈现为人话句子「当…且…→ 视为等价」;卡片 ⇄ 源码双视图双向同步,校验错误直接标在卡片上。

① 开始(空状态)— 设计要点
  • 1三入口收敛到同一流程,优先级分明:活动栏视图(按钮式引导,新手默认路径,标「推荐」)> Explorer 右键两步标记(复用官方「Select for Compare」心智)> 命令面板(进阶用户快捷路径,界面上不主动引导)。小白点图标就能走完全程,不需要记住任何命令名。
  • 2欢迎视图按钮 = 独占一行的链接:这是官方 Welcome View 的渲染规范(链接自动变按钮);「最近比较 / 收藏项目对」用 globalState 持久化,解决"两个项目反复比"的高频场景。(来源:Views UX / Welcome Views;Diff Folders 的 Favorites 模式)
  • 3按需激活:扩展声明视图后,用户点开视图才激活(onView 激活事件),符合官方"在语境合适的时机才激活"的要求。
② 选择文件(QuickPick)— 设计要点
  • 1自动嗅探 + 分组分隔:扫描两侧同名配置文件,用 QuickPick 分隔符按「两侧均存在 / 仅在一侧」分组,首选推荐项默认勾选。(来源:Quick Picks UX / separators;Common Capabilities / Quick Pick canSelectMany)
  • 2多选一次比较多对文件:底部固定键位提示(Enter / Esc),已选计数实时反馈。
  • 3进度不阻塞:比较执行用 withProgress 显示在通知区(或视图内),提供「取消」;完成/异常才用通知,遵循官方通知决策树"能不弹就不弹"。(来源:Notifications UX;Common Capabilities / Progress API)
③ 结果差异树 — 设计要点(核心画面)
  • 1树视图是官方推荐的结果展示形态:挂在活动栏自定义 View Container,打开才激活。(来源:Views UX「显示数据用 Tree View」)
  • 2四分区 + 双重计数:「值不同 / 类型不同 / 仅在 A / 仅在 B」分区标题带数量,视图标题徽标显示总数(16);这是 Compare Folders 验证过的三分区模型的扩展版。类型差异也可并回"值不同"区加徽标,二选一。
  • 3嵌套键保持原始层级:树层级 = 配置文件自身的嵌套结构,叶子节点显示「键: A值 → B值」单行摘要,避免官方警告的"不必要深层嵌套"(展示的是数据本身的层级)。
  • 4视图工具栏 4 个动作:刷新 ⟳ / 对调两侧 ⇄ / 树⇄列表切换 ≡ / 历史⋯;单条目内联动作不超过 3 个(官方红线),悬停才出现「打开对比 ⧉ / 忽略 ⊘」。(来源:Views UX Don't 清单)
  • 5状态三重编码:每条差异同时用 颜色(主题 token)+ 图标(≠ ⇄ − +)+ 文字,色盲与高对比度下仍可辨识。(来源:Accessibility / Color vision)
  • 6数千键导航:分区计数收敛全貌;「在树中定位」用 TreeView.reveal;QuickPick 模糊搜索键路径(Config Diff: Go to Key…)。(来源:TreeView API / reveal)
  • 7按文件 / 按状态双分组:默认按文件分组 —— 每个配置文件一个分区(含该文件的差异计数与状态小节),多文件时不迷路;工具栏 ◫ 一键切换为按状态(先看"哪些问题要修",文件嵌在其下)。两种模式的计数都从同一数据推导,永远一致。
④ Webview 报告表格 — 设计要点(第二期增强)
  • 1克制地用 Webview:只做原生树做不到的「键级扁平表格 + 计数过滤 + 搜索」,定位与侧边树互补,不重复其功能 —— 符合官方"Webview 仅在原生 API 不足时使用"。(来源:Webview 指南 / Should I use a webview)
  • 2过滤条带实时计数,一致项默认隐藏:12 处差异直接可扫;「显示一致项」是显式开关,避免 87 行噪音淹没 12 行信号。规则等价与已忽略各自独立成片,规则的影响一眼可见、可随时关闭。
  • 3大数据量策略:搜索 180ms 防抖、行虚拟化、5000 行上限提示 —— 全部是 JSON Diff Studio 用真实用户验证过的参数。(来源:JSON Diff Studio Marketplace)
  • 4行内四动作:打开内置 Diff ⧉ / 在树中定位 ⊙(reveal 双向联动)/ ≈ 设为等价(把眼前这对值写成值等价规则 —— 添加规则最常用的入口)/ 忽略 ⊘(写入忽略规则)。规则类动作即时生效,通知中确认。
  • 5零硬编码颜色:全部取自 --vscode-* CSS 变量(VS Code 自动注入 Webview),点上方「Light+ / High Contrast」即可验证自动适配。(来源:Webview Theming)
⑤ 键级 Diff 详情 — 设计要点
  • 1复用内置 diff 编辑器:树/表格条目用官方推荐的 vscode.diff 打开两侧值的虚拟文档对比 —— 并排视图、行号槽着色、概览标尺、Next Change 跳转、F7 无障碍差异查看器全部免费获得,且与内置文件对比观感一致。(来源:VS Code API / TreeItem.command 官方建议)
  • 2类型差异先声明再展示:虚拟文档头部加注释行「⇄ 类型不同: number (A) vs string (B)」,用 charts.orange,不与 error/warning 语义混淆;值差异行用 diff 插入/删除底色高亮。
  • 3连续排查:顶部「上一步 / 下一个差异」在多个键之间顺序跳转,修完一个到下一个,不需要来回找树。
  • 4单侧缺失:「仅在 A / 仅在 B」的键打开时,缺失一侧显示说明注释行,而不是空白 —— 避免用户误以为渲染出错。
⑥ 规则中心 — 设计要点
  • 1Schema 是契约,不是界面:规则底层用 JSONC + JSON Schema 表达(可校验、可补全、随 git 共享),但用户看到的是人话句子的规则卡片 ——「当 键 = … 且 A 值 = … → 视为等价」,永远不需要读 Schema。
  • 2双视图,双向同步:默认卡片视图;「源码」视图给进阶用户。卡片右上 {} 直达源码对应行并高亮;源码保存后卡片实时重渲染 —— 两个视图是同一份数据,不存在手工对齐。
  • 3校验错误落在卡片上:违反 Schema 的规则(如 values 与 coerce 互斥)在卡片上标红并给出原因与修复入口;无效规则不生效、不计入侧边栏计数 —— 运行中的规则永远可信。
  • 4表单由 Schema 驱动:「+ 添加规则」走 ⑦ 向导,字段、默认值、枚举选项都从 Schema 生成 —— Schema 写一次,表单与文档自动跟随,永不脱节。
  • 5命中透明 + 闭环:规则命中在结果区单独标注(≈ / ⊘ + 规则名,可随时停用);表格「忽略 ⊘」直接写回规则文件 —— 规则做了什么,随时可审计。
  • 6添加规则的两个入口:① 本屏「+ 添加规则」(侧边栏 + 或卡片工具栏)→ 打开 ⑦ 向导;② 结果驱动(最常用):报告表格行内「≈ 设为等价 / ⊘ 忽略」,从眼前的差异一键生成规则。刻意不做命令面板入口 —— 小白用户靠看得见的按钮,而非记住命令名;规则为空时,规则视图直接展示"添加"按钮引导。
⑦ 新建规则向导 — 设计要点
  • 1全程 QuickPick + InputBox:官方标准输入范式,简单规则 2-3 步串行输入完成,不需要打开编辑器、没有模态弹窗。
  • 2类型先行,逐步引导:先选规则类型(带"简单 / 进阶"分隔),再按步骤输入;作用范围默认全局,可用键路径模式限定。
  • 3即时反馈:完成后立即重新比较,并在结果中高亮"受此规则影响"的变化(≈ 紫色徽标 + 规则名),效果看得见。
  • 4从哪里进入向导:① 规则中心的「+ 添加规则」(侧边栏 + 或卡片工具栏);② 报告表格行内「≈ / ⊘」—— 带着差异上下文预填,最常用。刻意不做命令面板入口:小白用户靠看得见的按钮,而非记住命令名。
⑧ 脚本规则 — 设计要点(进阶,可选)
  • 1脚本就是普通 .js 文件:放在工作区里,享受完整 IntelliSense、Lint、git 管理;JSDoc 类型标注让编辑器给出参数提示 —— 扩展不需要自建脚本编辑器。
  • 2API 面刻意小:入参只有 {path, value, type},返回值只有 equal / different / ignore 三种 —— 心智负担最低,写错也不至于破坏比较流程。
  • 3保存即验证:自动对当前两侧结果"试运行",错误以诊断(红线)呈现,成功显示统计反馈;验证状态同步回规则中心的「✓ 已验证」徽标。
  • 4默认路径仍然简单:脚本规则排在向导最末位"进阶"分组,不用脚本的用户完全无感。
